How code moves from an upstream tool into K!larity:

1. **Vendor** — `ops/ci/vendor_upstream.py` copies only Adopt + Copy-with-attribution features, at a pinned commit, refusing `ee/`/`enterprise/` paths and banned files, into `third_party/<tool>/src/` with SHA-256 per file. Vendored files are never edited in place (CI enforces this).
2. **Review** — read the vendored feature against the owning EB task; decide keep / rewrite / drop.
3. **Adapt** — write K!larity code in the target path (tenant_id at every boundary, typed + versioned interfaces, no plaintext secrets), with a `Borrowed from:` line naming tool, commit and file.
4. **Record** — set the feature's `review:` state in `UPSTREAM.yaml` and add the notice to `THIRD_PARTY_NOTICES.md`.
